## 4. 残った4件の内訳

| 問題 | 理由 | 責任 |
|---|---|---|
| q030 | `age` を定義せず参照して実行エラー | **モデル** |
| q032 | 日次サマリと結合したまま `SUM(floor_area)` … 日数ぶん面積を二重に足している | **モデル** |
| q028 | 店舗の母集合が違う（37行と40行）。7月に取引の無い店舗を含めるか | 評価データ（残存） |
| q035 | 同上（1行と3行）。売上の無い閉店店舗を含めるか | 評価データ（残存） |

**2件は本物のモデルの誤り。** 特に q032 は、日次の行と結合したまま面積を合計しており、
分母が日数ぶん膨らむ。集計SQLで最も起きやすい種類の誤りで、これが取れるかは
モデルの実力を測るうえで意味がある。

**2件は「対象の母集合」という5つ目の曖昧さ。** ただし2/35（6%）であり、
**ここで評価データの改訂は打ち止めにする。** 改訂のたびに過去の実験と
比較できなくなるコストのほうが大きい。現在のスコアは 6% 程度の曖昧さを
含んでいる、と理解したうえで使う。

## 5. `comment` と `hint` の選択

| | comment | hint |
|---|---|---|
| 一致率 | 0.8857 | 0.8000 |
| 実行成功率 | 0.9714 | **1.0000** |
| トークン | 70,532 | **40,827（58%）** |

評価データが曖昧だった段階では両者の差が誤差に埋もれていたが、
**確定した状態では 3問（0.086）の差がついた。** 精度を採るなら `comment`。

トークンは `hint` が 42% 少ない。運用コストとの兼ね合いで選ぶ材料になる。
