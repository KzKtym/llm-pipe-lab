# demo_sales 診断フレームワーク — MECEな分解の型

- 日付: 2026-08-18
- 位置づけ: `README.md`「仕込んだ現実のノイズ」節と対になる文書。
  あちらは「データの癖」、こちらは「その癖を踏まえてどう分解するか」の型を記録する
  （段階1.5 の (b)）

## この文書の狙いと限界

小売の売上分析で繰り返し使う MECE な分解の型を **5件**に絞って文書化する。
**網羅を狙っていない。** 経営判断に100%の型は存在しない前提で、目的は
「ユーザーが吟味されていない質問をしないで済む水準」に引き上げること。
段階2の再設計では、曖昧さの判定をLLMの都度の総合判断ではなく、
この文書が持つ「既定の分解手順」を土台にした構造的な判定へ置き換える。

各パターンには次を明記する。

| 項目 | 内容 |
|---|---|
| 目的 | どんな意思決定に効くか |
| 対象データ列 | `demo_sales` のどのテーブル・どの列を使うか |
| 関連する落とし穴 | `README.md` の7つの落とし穴のうちどれに注意が要るか |

---

## 1. 売上分解（客数 × 客単価 × 購買頻度）

**目的**: 売上の増減が「客数が減ったのか」「単価が下がったのか」「1人あたりの
購入回数が減ったのか」のどれで説明できるかを切り分ける。値引きキャンペーンや
客層変化の影響を見るときの起点になる。

**対象データ列**: `sales.total_amount`（売上）、`sales.sale_id`（取引数）、
`sales.member_id`（会員か非会員か）、`members.member_code`（実人数）。

**関連する落とし穴**:

- **#3 非会員取引** — 「客数」を会員数で数えると、非会員取引（40% NULL）が
  分解から抜け落ちる。「客数」を取引数で数えるか実人数で数えるかを先に決める
- **#5 単価の二重持ち** — 「客単価」を `sales.total_amount` ベースで見るか、
  値引き後の実売（`sale_items.unit_price` × `quantity` − `discount_amount`）で
  見るかで、値引き施策の効果が客単価の下落として出るか出ないかが変わる

---

## 2. 地域・チャネル別の寄与度分解

**目的**: 全体の増減に対して、どのエリア・どの販売チャネルが最も寄与しているかを
特定する。「関西が落ちている」のような相談の裏取りに直結する。

**対象データ列**: `stores.region`（地域）、`sales.channel`（チャネル）、
`sales.total_amount`。

**関連する落とし穴**:

- **#1 表記ゆれ** — `region` の「関西」「近畿」、`channel` の「EC」「オンライン」を
  合算しないと、片方だけの数字で寄与度を誤読する。この2組は**データ上は別々の値**で、
  合算してよいという判断はコメント（意味の説明）に依存する（詳細は本書末尾の対応表）

---

## 3. 値引き施策の効果測定

**目的**: 値引き（定価と実売の差）が販売数量・売上にどれだけ影響したかを測る型。
「値引きは効いているのか」という相談に直接答える。

**対象データ列**: `products.unit_price`（定価）、`sale_items.unit_price`（実売単価）、
`sale_items.discount_amount`、`sale_items.quantity`。

**関連する落とし穴**:

- **#5 単価の二重持ち** — 定価と実売単価は29.4%の明細で不一致（`PROFILING.md` 観点4-e）。
  「値引き」を `discount_amount` で見るか、定価と実売単価の差で見るかで定義が変わる
  （両者は独立ではなく重なりうるため、二重計上に注意）

---

## 4. 稼働店舗ベースの店舗パフォーマンス比較

**目的**: 店舗ごとの売上・日商を比較して、テコ入れが要る店舗を特定する。
「平均日商」の分母（稼働日数の数え方）次第で順位が変わりうる型。

**対象データ列**: `daily_store_summary`（サマリ由来の平均を出す場合）、
`sales` + `stores`（明細から作り直す場合）、`stores.close_date`（閉店の有無）。

**関連する落とし穴**:

- **#4 論理削除・フラグ** — 閉店済み店舗（`close_date` 非NULL、3件）を比較対象に
  含めるかどうかで平均が変わる
- **#6 粒度違い** — `daily_store_summary` は取引ゼロの店舗×日の行を持たない疎テーブル
  （`PROFILING.md` 観点6：38店×730日=27,740の理論値に対し実行数25,624、差2,116）。
  サマリだけで平均日商を出すと、取引ゼロ日が母数から落ちて過大になる

---

## 5. 時間整合チェック（必須パターン）

**目的**: 実績データ（`sales`）が、マスタが持つライフサイクル日付
（商品の発売日、会員の入会日、店舗の開店日・閉店日）と矛盾していないかを確認する型。
他の分解を行う**前提チェック**として使う。ここが崩れていると、以降の分解すべての
信頼性が揺らぐ。

**対象データ列**: `products.launch_date`、`members.join_date`、
`stores.open_date` / `close_date`、`sales.sold_at`。

**関連する落とし穴**:

- **#7 日付境界** — `sold_at` は時刻つき（timestamp）。日単位で集計する境界の取り方
  （`sold_at::date` か `>= 開始 AND < 翌日` の半開区間か）で当日23時台の扱いが変わる

**除外の明記が必須（`README.md`「仕込みではない既知の不整合」）**:

`demo_sales` には、時間整合チェックを実際に流すと検出される、**仕込みではない**
不整合が2件ある。

| 所見 | 件数 | 母数に対する割合 |
|---|---:|---|
| 発売前販売（`sales.sold_at` < `products.launch_date`） | **4,494件** | 明細198,491件の 2.3% |
| 入会前購入（`sales.sold_at` < `members.join_date`） | **4,124件** | 会員取引47,966件の 8.6% |

**この2件は、7つの落とし穴のように意図して設計した業務シナリオではない。**
`gen_sales_data.py` が商品・会員を売上日と無関係にランダム割り当てした
**生成スクリプトの偶発的な不備（バグ）**であり、盲検プロファイリング（[付録05](../../docs/appendix/05_blind_profiling.md)）で
偶然見つかった（詳細は `README.md` 該当節）。**このパターンを実行するたびに、
この2件を除外するかどうかを都度明記すること。** 明記が無いと同じ問いに違う数字が出る。

（参考: 店舗の開店前・閉店後の取引は0件で、店舗ライフサイクルとの整合は取れている。
時間整合の問題は商品・会員側にのみ存在する。）

## 対応表：診断パターンと7つの落とし穴

| # | パターン | 関連する落とし穴 |
|---|---|---|
| 1 | 売上分解（客数×客単価×頻度） | #3 非会員取引、#5 単価の二重持ち |
| 2 | 地域・チャネル別の寄与度分解 | #1 表記ゆれ |
| 3 | 値引き施策の効果測定 | #5 単価の二重持ち |
| 4 | 稼働店舗ベースの店舗パフォーマンス比較 | #4 論理削除・フラグ、#6 粒度違い |
| 5 | 時間整合チェック | #7 日付境界、（仕込み外の不整合2件） |

**#2 欠損は5パターンいずれにも直接の主役として現れない。** 会員属性
（`gender` / `birth_date`）の分析パターンを追加すれば関連するが、今回の5件には
未収録（網羅を狙わない方針のため、意図的に外している）。

## 既定ポリシー：母集合が質問文で決まっていないとき

質問文が対象の母集合を確定させていない場合、**聞き返さずに既定で答え、その前提を開示する。**
聞き返すのは、既定を決められない型だけに絞る。

素の業務質問は**7割で母集合が未確定**であり（35問中25問）、
毎回聞き返す設計は成立しない。一方で黙って解釈すれば、
`../../docs/Concept_and_Overview.md` 1節が害だとした「抜けた行」がそのまま起きる。

### `types` が指すもの（盲検セット4本目の時点で確定）

> **`types` が指すのは「既定を当てて開示すべきか」の一点のみ。
> 出力の顔ぶれが変わるかどうかは型1の内部的な根拠であって、判定基準そのものではない。**

**「顔ぶれ（ロスター）」を、型2〜4まで含めた汎用の判定基準に広げてはいけない。**

`../../docs/Concept_and_Overview.md` 3節の起点がそれを示している。
「関西の売上が落ちています」の裏で「近畿」表記の店舗が抜けていた——**これは単一値の
集計で、顔ぶれという概念が無い。害の中身は最初から「値が静かに違う」であって
「行が消える」ではなかった。**

この一文が無いまま「顔ぶれ」と「型2は軸と無関係に見る」を並べて依頼書に書いたため、
**盲検セットごとにラベルの基準が割れた**（2本目・4本目は顔ぶれで読み、
`population_labels`・3本目は開示で読んだ）。**次に基準を書く人のための1行である。**

### 型ごとの既定

| 型 | 内容 | 既定 |
|---|---|---|
| **1** | 結合で行が消える（実績の無い実体を並べるか） | **既定を置かない。聞き返す** |
| **2** | フラグで行を除くか（`close_date` / `is_discontinued` / `is_active`） | 下記の切り分け |
| **3** | 値の同義性（`region` の関西/近畿、`channel` の EC/オンライン） | **統合する** |
| **4** | 包括値・`NULL`（`members.pref` の「その他」、`gender` の「その他」と未登録） | **除外せず、独立した区分として表示する** |

### 型2の切り分け

> **実体そのものを数える、または実体を並べて比較・順位づけする**（トップN・ランキングを含む）
> → **現役のみ**
>
> **実体を主語にせず、事象の集計値そのものを問う**（売上合計・構成比・平均・比率）
> → **全部含める**

**判定の鍵は「数える対象が実体か、事象か」。** 並べる軸が区分（大分類・会員ランク・
店舗形態・都道府県）かどうかではない。

| 設問 | 数える対象 | 既定 |
|---|---|---|
| 店舗は全部で何店舗ある？ | 実体（店舗） | 現役のみ |
| 会員数を会員ランク別に | 実体（会員） | 現役のみ |
| 取引件数が多い店舗トップ5 | 実体を並べる | 現役のみ |
| 最も売れた商品トップ10 | 実体を並べる | 現役のみ |
| 面積あたり売上を高い順に | 実体を並べる | 現役のみ |
| 商品大分類ごとの売上金額 | 事象（売上） | 全部含める |
| 会員ランク別の平均客単価 | 事象（客単価） | 全部含める |
| 各年代の売上構成比 | 事象（売上） | 全部含める |

**同じ「〜別」でも、数えるものが違えば既定が逆になる。**
「会員ランク別の会員数」は現役のみ、「会員ランク別の客単価」は全部含める。
論理は一貫しているが利用者には分かりにくいので、**開示文で必ず前提を示すこと。**

### 型1を既定に倒さない理由

実績の無い実体を含めるかは、母集合の大小だけでなく**指標の意味そのもの**を変える。
「稼働日平均」と「暦日平均」は別の指標であり、どちらかが正解というより目的次第。
段階2が元々スコープにしていた唯一の型でもあり、**聞き返す価値が最も高い。**

### 開示文の形

答えを返したうえで、当てた既定と、変える手段を示す。

```
閉店した店舗を除いて集計しました。含める場合はお知らせください。      （型2・現役のみ）
廃番になった商品も含めて集計しました。除く場合はお知らせください。    （型2・全部含める）
「近畿」表記の店舗も関西として合算しました。分ける場合はお知らせください。（型3・統合）
都道府県が「その他」の会員1,048人は、独立した区分として表示しています。（型4）
```

**どちら向きの既定でも開示する。** 除外を黙るのと同じく、**含めたことを黙るのも同じ害**になる。
統合したこと、独立区分として出したことも同様。**当てた既定は、向きに関わらず必ず告げる。**

告げない答えは、`../../docs/Concept_and_Overview.md` 1節の「抜けた行が害になる」に逆戻りする。

### 適用範囲の注意

- 型4の対象は **`members.pref` と `gender` の2列**。`floor_area` / `birth_date` の `NULL` は
  「グループ化の区分」ではなく「平均の分母に含めるか」という別種の論点で、ここには含めない
- **時間軸**（日付列から導いたグループ化）は型1として扱う。カレンダーの顔ぶれを
  質問文が確定させていなければ聞き返す
- **`gold_sql` は既定の出典にならない。** 段階1の正解は「質問文に書いていないことは何もしない」
  素直な変換で、業務的な既定を体現していない（`AD_Nl2Sql_Design` 8節）。
  同じ質問でも**段階1の正解と製品の既定は食い違う**（「店舗は全部で何店舗ある？」は
  段階1で40、製品で37）
