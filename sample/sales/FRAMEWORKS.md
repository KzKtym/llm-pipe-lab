## この文書の使い方

各項目には次を書く。

| 項目 | 内容 |
|---|---|
| 名称 | 実務・文献で確立された呼び方（英語表記も併記） |
| 答える経営判断 | この手法が明らかにする意思決定は何か |
| 典型的な変数・切り口 | 分析に使う典型的なデータ項目（このDBにあるかどうかは問わない） |
| 何をする手法か | 1〜2文の説明 |

**このDBに実在するかどうかは、ここでは判定しない。** それは `PROFILING.md`・
`schema_hints.md`（右辺）との掛け合わせで別途行う（段階1.5 の設計方針）。
この文書はあくまで「一般に何が確立されているか」だけを記す。

## 1. 売上分解（ドライバーツリー／KPIツリー）

| | |
|---|---|
| **名称** | 売上ドライバーツリー分解（Sales Driver Tree / KPI Tree）。小売の代表形は
  **客数 × 客単価 × 購買頻度**、EC の代表形は **トラフィック × コンバージョン率 × 客単価** |
| **答える経営判断** | 売上の増減が「客数が減ったのか」「単価が下がったのか」「頻度が落ちたのか」の
  どれで説明できるか |
| **典型的な変数・切り口** | 取引数、実人数、購入頻度、客単価（実収ベース） |
| **何をする手法か** | 売上を掛け算で分解し、どの因子が変化の主因かを切り分ける。
  最も基本的な診断の型で、多くの他の手法の出発点になる |

## 2. RFM分析（Recency, Frequency, Monetary）

| | |
|---|---|
| **名称** | RFM分析 |
| **答える経営判断** | どの顧客が優良か、離反しかけている顧客は誰か。CRM・リテンション施策の
  対象を絞る |
| **典型的な変数・切り口** | 直近購入日（Recency）、購入頻度（Frequency）、購入金額
  合計（Monetary） |
| **何をする手法か** | 顧客をこの3軸でスコア化し、優良顧客・休眠顧客等のセグメントに分ける |

## 3. コホート分析

| | |
|---|---|
| **名称** | コホート分析（Cohort Analysis） |
| **答える経営判断** | 新規獲得した顧客の質は改善しているか悪化しているか。
  リテンションは時系列で良くなっているか |
| **典型的な変数・切り口** | 初回購入月（会員登録月）、以降の各月の購入有無 |
| **何をする手法か** | 顧客を獲得時期でグループ化し、時間経過に伴う継続率・再購買率を追う |

## 4. ABC分析（パレート分析）

| | |
|---|---|
| **名称** | ABC分析／パレート分析 |
| **答える経営判断** | どの商品・店舗・顧客に経営資源（在庫・棚・販促）を優先配分すべきか |
| **典型的な変数・切り口** | 商品別・店舗別・顧客別の売上（または利益）と、その累積構成比 |
| **何をする手法か** | 対象を売上寄与度順に並べ、累積構成比でA/B/Cにランク分けする
  （上位2割が売上の8割を占める、という経験則が背景） |

## 5. 地域・チャネル別の寄与度分解

| | |
|---|---|
| **名称** | セグメント別寄与度分解（Contribution / Waterfall Analysis） |
| **答える経営判断** | 全体の増減に対して、どのエリア・チャネル・カテゴリが最も寄与しているか |
| **典型的な変数・切り口** | 地域、チャネル、商品カテゴリ、店舗形態などの区分軸 |
| **何をする手法か** | 全体の変化額を区分ごとに割り、寄与度の大きい区分を特定する |

## 6. マーケットバスケット分析（アソシエーション分析）

| | |
|---|---|
| **名称** | マーケットバスケット分析（Market Basket Analysis） |
| **答える経営判断** | どの商品が一緒に買われているか。クロスセル・商品配置・バンドル施策に使えるか |
| **典型的な変数・切り口** | 同一取引内の商品の組み合わせ（支持度・確信度・リフト値） |
| **何をする手法か** | 取引明細から同時購入の頻出パターンを抽出する |

## 7. 価格弾力性・値引き効果測定

| | |
|---|---|
| **名称** | 価格弾力性分析／プロモーション効果測定 |
| **答える経営判断** | 値引き・キャンペーンは数量・売上をどれだけ押し上げたか。
  値引き無しの場合と比べて net でプラスだったか |
| **典型的な変数・切り口** | 定価、実売単価、値引額、販売数量、施策期間の前後比較 |
| **何をする手法か** | 価格変化と数量変化の関係を見る、または施策期間とそれ以外を比較する |

## 8. 店舗パフォーマンス比較

| | |
|---|---|
| **名称** | 店舗パフォーマンス比較（坪効率／稼働店舗ベース比較） |
| **答える経営判断** | どの店舗がテコ入れを要するか。閉店・出店の判断材料 |
| **典型的な変数・切り口** | 店舗別売上、店舗面積（坪効率）、稼働日数、開店・閉店日 |
| **何をする手法か** | 店舗を正規化した指標（面積あたり・稼働日あたり）で比較する。
  閉店済み店舗を含めるかどうかで平均が変わる点に注意が要る |

## 9. 季節性・トレンド分析（時系列分解）

| | |
|---|---|
| **名称** | 時系列分解（トレンド・季節性・残差） |
| **答える経営判断** | 見えている増減は一時的な季節変動か、構造的なトレンドか |
| **典型的な変数・切り口** | 日次・週次・月次の売上時系列、曜日、月、祝日・イベントの有無 |
| **何をする手法か** | 時系列をトレンド成分・季節成分・残差に分解し、異常かどうかを判定する |

## 10. 顧客生涯価値（LTV）

| | |
|---|---|
| **名称** | 顧客生涯価値（Customer Lifetime Value, LTV） |
| **答える経営判断** | 1人の顧客獲得・維持にどこまで投資してよいか |
| **典型的な変数・切り口** | 平均購入頻度、平均客単価、継続期間（会員の場合は入会日〜離脱） |
| **何をする手法か** | 顧客の将来の購買を見積もり、生涯を通じた価値を金額化する |

## 11. 顧客セグメンテーション

| | |
|---|---|
| **名称** | 顧客セグメンテーション（デモグラフィック／行動ベース） |
| **答える経営判断** | 中核顧客層はどこか。特定の層だけ落ち込んでいないか |
| **典型的な変数・切り口** | 年代、性別、会員ランク、居住地域、購買行動（頻度・単価） |
| **何をする手法か** | 属性または行動で顧客を分け、セグメントごとに指標を比較する |

## 12. 需要予測・予実分析

| | |
|---|---|
| **名称** | 需要予測（Demand Forecasting）／予実分析（Budget vs. Actual, Variance Analysis） |
| **答える経営判断** | このままのペースで今期の目標に届くか。計画と実績の差はどこで生まれたか |
| **典型的な変数・切り口** | 実績の時系列、目標値・予算値、達成率、期中の進捗ペース |
| **何をする手法か** | 過去の実績から将来を延伸する、または実績を計画値と突き合わせて差異を要因分解する |

## 13. 収益性・粗利分析

| | |
|---|---|
| **名称** | 収益性分析（カテゴリ別・商品別粗利率） |
| **答える経営判断** | 売れているが儲かっていない商品・カテゴリはどれか |
| **典型的な変数・切り口** | 売上、原価（仕入価格）、粗利、粗利率 |
| **何をする手法か** | 売上だけでなく原価を突き合わせ、利益ベースで優先順位をつけ直す |

## 14. 商圏・立地分析

| | |
|---|---|
| **名称** | 商圏分析／立地分析（Trade Area Analysis） |
| **答える経営判断** | 店舗の立地特性（オフィス街か住宅街か、競合の有無）が
  業績にどう影響しているか。出店・閉店の判断材料 |
| **典型的な変数・切り口** | 店舗所在地、周辺人口・世帯構成、競合店の有無、来店手段（徒歩・車） |
| **何をする手法か** | 店舗の立地属性と業績を突き合わせ、立地要因の影響を見る |

## 15. 市場・競合比較

| | |
|---|---|
| **名称** | 市場シェア分析／競合ベンチマーキング |
| **答える経営判断** | 自社の伸び・鈍化は、市場全体の動きか自社固有の問題か |
| **典型的な変数・切り口** | 自社実績、業界・市場全体の統計、競合の公開情報 |
| **何をする手法か** | 自社の指標を外部の市場・競合データと比較し、相対的な位置を確認する |

## 意図的に含めていないもの

**時間整合チェック**（`DIAGNOSIS.md` パターン5）は、ここに載せていない。
**あれは分析の型ではなく、実績データがマスタのライフサイクル日付と矛盾していないかの
データ検証であり、右辺（`PROFILING.md`・データ品質）の領分である。** `DIAGNOSIS.md`
の5パターンのうち、この1つだけが左辺（本書）に対応物を持たないのは、この違いによる
（段階1.5 の設計方針の再導出で確認すべき点の1つ）。
